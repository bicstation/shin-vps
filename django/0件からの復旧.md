SHIN CORE LINX｜LOCAL PostgreSQL DB 0件問題・復旧記録

発生事象

自宅PC（Marya）の LOCAL 環境で shin_core_local の api_pcproduct が 0件 になる現象が発生。

構成確認

Compose の PostgreSQL は以下の bind mount を使用。

/home/maya/shin-dev/vps-data/postgres
    ↓
/var/lib/postgresql/data

Django の接続先も正常。

DB_HOST=postgres-db-v3
DB_NAME=shin_core_local
DB_USER=tiper_user
DB_PORT=5432

決定的な発見

ホスト側には本物の PostgreSQL データが残っていた。

/home/maya/shin-dev/vps-data/postgres/base/17318
約200MB

一方、異常な PostgreSQL コンテナでは、

/var/lib/postgresql/data
    ↓
tmpfs

となっていた。

確認コマンド：

docker exec shin-local-postgres-db-v3-1 cat /proc/mounts | grep '/var/lib/postgresql/data'

異常時：

none /var/lib/postgresql/data tmpfs rw,relatime 0 0

docker inspect では bind mount が正常に表示されていたため、inspect だけでは異常を発見できなかった。

同じホストディレクトリを Alpine の一時コンテナへ bind mount したところ、

/dev/sdd /test-postgres ext4 ...

となり、base/17318 の約200MBが正常に見えた。

したがって、Docker の bind mount 自体やホスト側データが壊れていたのではなく、古い shin-local-postgres-db-v3-1 コンテナ固有の mount 状態が異常だったと判断。

復旧

DB データを削除せず、PostgreSQL コンテナだけを再生成。

docker compose -p shin-local stop postgres-db-v3
docker compose -p shin-local rm -f postgres-db-v3
docker compose -p shin-local up -d postgres-db-v3

再生成後：

/dev/sdd /var/lib/postgresql/data ext4 ...

となり、正常な永続領域へ復帰。

DB 復旧確認

PostgreSQL はホスト側の本物の DB を認識。

oid  | datname
-----+----------------
1    | template1
4    | template0
5    | postgres
17318| shin_core_local

そして、

SELECT COUNT(*) FROM api_pcproduct;

結果：

5211

データは消失していなかった。

原因

【異常時】

shin-local-postgres-db-v3-1
        ↓
/var/lib/postgresql/data
        ↓
tmpfs
        ↓
別の一時的な DB
        ↓
shin_core_local = 0件


【復旧後】

shin-local-postgres-db-v3-1
        ↓
/var/lib/postgresql/data
        ↓
/dev/sdd ext4
        ↓
/home/maya/shin-dev/vps-data/postgres
        ↓
base/17318
        ↓
shin_core_local
        ↓
api_pcproduct = 5211件

今後の LOCAL DB 障害対応

「DB が 0 件」になった場合、すぐに DB 削除・再初期化を行わない。

まず以下を確認する。

Django の DB 接続先

docker exec -it shin-local-django-v3-1 python manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default'])"

PostgreSQL の DB

docker exec -it shin-local-postgres-db-v3-1 psql -U tiper_user -d postgres -c "SELECT oid, datname FROM pg_database;"

PostgreSQL の実 mount

docker exec shin-local-postgres-db-v3-1 cat /proc/mounts | grep '/var/lib/postgresql/data'

Docker の mount 定義

docker inspect shin-local-postgres-db-v3-1 --format '{{range .Mounts}}{{printf "TYPE=%s SOURCE=%s DEST=%s RW=%v\n" .Type .Source .Destination .RW}}{{end}}'

ホスト側データ

sudo du -sh /home/maya/shin-dev/vps-data/postgres
sudo sh -c 'du -sh /home/maya/shin-dev/vps-data/postgres/base/*'

bind mount の独立検証

docker run --rm   -v /home/maya/shin-dev/vps-data/postgres:/test-postgres   alpine:3.22   sh -c 'cat /proc/mounts | grep /test-postgres; cat /test-postgres/PG_VERSION; ls -lah /test-postgres/base'

原因確認前に実行しないこと

docker compose down -v
docker volume prune
docker system prune
DB ディレクトリ削除
PostgreSQL データ削除

まず、

「データが本当に消えたのか」
「PostgreSQL が別の Filesystem を見ているだけなのか」

を切り分ける。

最終結果

データ消失ではない
DB設定不一致ではない
Compose volume定義の誤りではない
Docker bind mount機能の故障ではない

→ 古い PostgreSQL コンテナの mount 状態異常
→ PostgreSQL コンテナ再生成で正常化
→ shin_core_local 5211件を復旧
