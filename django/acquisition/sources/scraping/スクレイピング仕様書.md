# SHIN CORE LINX Scraping Specification

---

# 1. Purpose

The purpose of the Scraping Framework is to preserve Reality.

Scraping must never generate semantic meaning.

Reality is acquired first.

Meaning is generated later by AI Runtime.

---

# 2. Core Philosophy

Reality is acquired differently.

Reality is preserved consistently.

Meaning is generated later.

Every Runtime has a single responsibility.

---

# 3. Source Architecture

Each scraping source owns its own implementation.

Different sources may have different:

- Directory structures
- Runtime pipelines
- Fetch methods
- HTML parsers
- Observation strategies

The framework does NOT require identical implementations.

Only responsibilities are standardized.

---

# 4. Runtime Pipeline

Reality
    ↓
Acquire Runtime
    ↓
Observation Runtime
    ↓
ObservationDocument
    ↓
Import Runtime
    ↓
PCProduct
    ↓
AI Runtime
    ↓
Specification Runtime
    ↓
Semantic Runtime

The actual implementation pipeline may differ by source.

---

# 5. Runtime Responsibilities

## Acquire Runtime

Responsibilities

- Download source pages
- Acquire Reality
- Save raw HTML if necessary

MUST NOT

- Classify
- Normalize meaning

---

## Observation Runtime

Responsibilities

- Extract observable Reality
- Build ObservationDocument
- Produce observation_runtime

MUST

- Preserve Reality

MUST NOT

- Classify
- Infer
- Guess
- Generate semantic meaning

---

## Import Runtime

Responsibilities

- Translate Runtime Contracts
- Persist PCProduct

---

## AI Runtime

Responsibilities

- Read observation_runtime
- Extract Specifications
- Classify Reality

AI Runtime is the first Runtime allowed to generate meaning.

---

## Semantic Runtime

Responsibilities

- Generate Semantic Runtime
- Generate Semantic Labels
- Generate Semantic Profiles

Semantic Runtime never parses HTML.

---

# 6. ObservationDocument

ObservationDocument is a temporary representation
of observable Reality.

It exists only during acquisition.

Observation Runtime is the persistent representation
stored inside PCProduct.

ObservationDocument

↓

Observation Runtime

↓

PCProduct

---

# 7. Observation Runtime

Observation Runtime is a Reality snapshot.

Typical fields

- url
- title
- description
- images
- tables
- scripts
- main_image

Field names may differ by source.

Source-specific structures should be preserved.

Observation Runtime is the primary AI input.

---

# 8. Design Principles

Reality First

Observation First

Meaning Before Runtime

Translation Authority

Backend is Semantic Authority.

Observation Runtime never performs classification.

AI Runtime performs classification.

---

# 9. Adding a New Source

Recommended order

1. Create Source
2. Implement Fetch
3. Implement Observation
4. Produce ObservationDocument
5. Produce Observation Runtime
6. Persist PCProduct
7. Verify UI
8. Verify Affiliate Link
9. Verify AI Runtime

---

# 10. Validation Checklist

□ HTML acquired

□ ObservationDocument generated

□ Observation Runtime generated

□ Import Contract generated

□ PCProduct persisted

□ Observation Runtime persisted

□ API verified

□ UI verified

□ Images verified

□ Prices verified

□ Affiliate Link verified

□ Product Page verified

□ AI Runtime verified

□ Semantic Runtime verified

# スクレイピング仕様書

---

# 1. 目的

SHIN CORE LINX のスクレイピングは、
意味を生成することが目的ではありません。

Reality（現実）を取得し、
可能な限り失わず保存することが目的です。

意味の生成はAI Runtimeが担当します。

---

# 2. 基本思想

Realityの取得方法は
サイトごとに異なります。

しかし、

Realityの保存思想は
すべてのサイトで共通です。

意味は後から生成します。

各Runtimeは
一つの責務だけを担当します。

---

# 3. ソース毎のアーキテクチャ

各スクレイピングサイトは
独立した実装を持ちます。

サイトごとに

・ディレクトリ構成

・Pipeline

・取得方法

・HTML解析方法

・Observation生成方法

は異なって構いません。

Pipelineを統一することは目的ではありません。

統一するのは責務です。

---

# 4. Runtime全体像

Reality
    ↓
Acquire Runtime
    ↓
Observation Runtime
    ↓
ObservationDocument
    ↓
Import Runtime
    ↓
PCProduct
    ↓
AI Runtime
    ↓
Specification Runtime
    ↓
Semantic Runtime

サイトごとに
Pipelineの実装は異なって構いません。

---

# 5. Runtimeの責務

## Acquire Runtime

役割

・Reality取得

・HTML取得

・必要に応じてHTML保存

行わないこと

・分類

・意味付け

---

## Observation Runtime

役割

・Reality抽出

・ObservationDocument生成

・Observation Runtime生成

行うこと

・Reality保存

行わないこと

・分類

・推測

・補完

・意味付け

---

## Import Runtime

役割

・Runtime Contract変換

・PCProduct保存

---

## AI Runtime

役割

Observation Runtimeを入力として

Realityを分類します。

CPU

GPU

メモリ

ブランド

シリーズ

AI PC判定

などはAI Runtimeの責務です。

AI Runtimeが
初めて意味を生成できるRuntimeです。

---

## Semantic Runtime

役割

Semantic Runtime生成

Semantic Label生成

Semantic Profile生成

HTML解析は行いません。

---

# 6. ObservationDocument

ObservationDocumentは

スクレイピング中だけ存在する

Realityの一時オブジェクトです。

PCProductへ保存される

Observation Runtimeとは異なります。

ObservationDocument

↓

Observation Runtime

↓

PCProduct

という流れになります。

---

# 7. Observation Runtime

Observation Runtimeは

Realityのスナップショットです。

保存される内容の例

・URL

・タイトル

・説明

・画像

・スペック表

・JSON-LD

・Script

など

サイトごとに取得できる情報は異なります。

取得できたRealityは
可能な限りそのまま保存します。

Observation Runtimeは

AI Runtimeの入力データになります。

---

# 8. 設計原則

Reality First

Observation First

Meaning Before Runtime

Translation Authority

BackendはSemantic Authorityです。

Observation Runtimeでは

分類を行いません。

分類はAI Runtimeが担当します。

---
