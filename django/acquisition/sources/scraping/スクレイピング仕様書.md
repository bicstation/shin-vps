# Reality Acquisition Framework Specification

Version 3.0

---

# Purpose

This specification defines the framework responsible for
acquiring Reality from external sources.

The framework preserves Reality.

It never generates semantic meaning.

It never interprets products.

Its responsibility ends when the Integration Runtime
produces the Import Contract consumed by
the Product Runtime.

---

# Framework Boundary

```
Reality Sources
        │
        ▼
Reality Acquisition Framework
        │
        ▼
Import Contract
══════════════════════════════════════
Framework Boundary
══════════════════════════════════════
        │
        ▼
Product Runtime
```

Everything after the Import Contract is defined by
the Product Runtime Specification.

---

# Design Philosophy

Reality First

Observation First

Document First

Runtime Contract First

Single Responsibility

Translation Authority

Framework Boundary

# Core Principles

The framework acquires Reality.

The framework preserves Reality.

The framework never creates meaning.

Meaning begins only inside the AI Runtime.

Every Runtime owns exactly one responsibility.

Implementations may evolve.

# Reality Sources

Reality may originate from many different sources.

Examples

- Manufacturer Websites
- Retail Shops
- Affiliate Networks
- REST APIs
- FTP Feeds
- CSV Imports
- HTML Documents

Reality Sources are independent.

Each source owns its own implementation.

The framework standardizes responsibilities.

It does not standardize acquisition methods.

---

# Source Independence

Every Reality Source may use its own technology.

Examples

- Playwright
- Requests
- FTP
- REST API
- GraphQL
- Browser Automation

The acquisition method is implementation.

Reality preservation is responsibility.

# Reality Acquisition Pipeline

The Reality Acquisition Framework transforms
external Reality into an Import Contract.

The framework preserves Reality.

Every Runtime owns one responsibility.

```
Reality
        │
        ▼
Fetch Runtime
        │
        ▼
Acquire Runtime
        │
        ▼
Observation Runtime
        │
        ▼
Formatter Runtime
        │
        ▼
Mapper Runtime
        │
        ▼
Integration Runtime
        │
        ▼
Import Contract
```

The Integration Runtime is the final Runtime
defined by this specification.

---

# Acquire Pipeline

Each Runtime produces exactly one output.

Each Runtime consumes exactly one input.

Adjacent Runtimes communicate only through
Runtime Contracts.

A Runtime must never access the internal
implementation of another Runtime.

# Runtime Overview

## 01. Fetch Runtime

Responsibilities

- Access Reality Sources
- Download Reality
- Preserve Original Content
- Produce Acquisition Documents

Never

- Parse HTML
- Normalize Data
- Generate Meaning

Typical Outputs

- HTML
- JSON
- CSV
- XML
- FTP Files

---

## 02. Acquire Runtime

Responsibilities

- Discover Acquisition Units
- Split large Reality into Runtime Documents
- Preserve acquisition boundaries

Examples

- Catalog Runtime
- Category Runtime
- Card Discovery

Never

- Interpret Products
- Normalize Text
- Generate Semantic Meaning

---

## 03. Observation Runtime

Responsibilities

- Observe Reality
- Parse Documents
- Extract Observable Fields

Examples

- raw_title
- raw_price
- raw_image
- raw_detail_url
- raw_specs
- raw_labels
- raw_html

Observation preserves Reality exactly as observed.

Observation never performs normalization.

Observation never generates meaning.

---

## 04. Formatter Runtime

Responsibilities

- Normalize Runtime
- Normalize Text
- Normalize Collections
- Runtime Safety

Formatter preserves Reality.

Formatter changes formatting only.

Formatter never changes meaning.

---

## 05. Mapper Runtime

Responsibilities

- Translate Runtime Contracts
- Build Canonical Runtime
- Normalize URLs
- Normalize Prices
- Generate Affiliate URLs

Mapper is the Translation Authority.

Mapper never performs semantic classification.

---

## 06. Integration Runtime

Responsibilities

- Build Import Contracts
- Execute Import Service
- Produce Import Documents

Integration Runtime is the final Runtime
defined by the Reality Acquisition Framework.

Everything after this Runtime belongs to
the Product Runtime Specification.

# Runtime Contracts

The Runtime Contract is the only supported
communication interface between adjacent Runtimes.

Implementations may change.

Runtime Contracts should remain stable.

---

# Runtime Contract Principle

Every Runtime owns

- one Input Contract
- one Output Contract

A Runtime communicates only through
its Runtime Contract.

A Runtime must never depend on the internal
implementation of another Runtime.

```
Input Contract
        │
        ▼
Runtime
        │
        ▼
Output Contract
```

---

# Acquisition Documents

Reality is preserved as Runtime Documents.

Each Runtime produces its own
AcquisitionDocument.

Typical document flow

```
Reality

        │

        ▼

AcquisitionDocument(catalog)

        │

        ▼

AcquisitionDocument(catalog_runtime)

        │

        ▼

AcquisitionDocument(cards)

        │

        ▼

AcquisitionDocument(observation)

        │

        ▼

AcquisitionDocument(formatter)

        │

        ▼

AcquisitionDocument(mapper)

        │

        ▼

ImportDocument(product)
```

The document structure belongs to the producing Runtime.

Each document is immutable Reality
for the next Runtime.

# Purpose

This specification defines the naming conventions used
throughout the Reality Acquisition Framework.

- readability
- maintainability

Reality

Meaning.

responsibility,

---

# Runtime Naming

Runtime names use

Pascal Case.

Examples

- Fetch Runtime
- Acquire Runtime
- Observation Runtime
- Formatter Runtime
- Mapper Runtime
- Integration Runtime

Avoid implementation-specific names.

Examples

Avoid

- HTML Runtime
- BeautifulSoup Runtime
- Playwright Runtime

Those describe implementation,
not responsibility.

---

# Python Module Naming

Python modules use

snake_case.

Examples

```
fetch_catalog.py

discover_catalog.py

discover_cards.py

observe_cards.py

formatter.py

mapper.py

integration.py

pipeline.py

run.py

settings.py
```

Module names should describe
their Runtime responsibility.

# Framework Design Principles

# Purpose

This section defines the architectural principles
that govern the Reality Acquisition Framework.

These principles are implementation-independent.

Every Runtime should follow them consistently.

---

# Principle 01

Reality First

Reality is acquired exactly as published.

The framework never modifies Reality.

Reality must remain reproducible.

---

# Principle 02

Observation Before Interpretation

Observation records

what exists.

It never explains

why it exists.

Interpretation belongs to later Frameworks.

---

# Principle 03

Document First

Reality moves through the framework
as Runtime Documents.

```
Reality

↓

AcquisitionDocument

↓

AcquisitionDocument

↓

ImportDocument
```

Every Runtime receives
a Runtime Document.

Every Runtime produces
a Runtime Document.

Documents represent Reality.

---

# Principle 04

Runtime Contract First

Runtime communication occurs only through
Runtime Contracts.

```
Runtime

↓

Output Contract

↓

Next Runtime
```

A Runtime never depends upon

- source code

- helper functions

- internal implementation

of another Runtime.

---

# Principle 05

Single Responsibility

Every Runtime owns
exactly one responsibility.

Examples

Fetch Runtime

↓

Acquire Reality

Observation Runtime

↓

Observe Reality

Formatter Runtime

↓

Normalize Reality

Mapper Runtime

↓

Translate Reality

Integration Runtime

↓

Produce Import Contract

Responsibilities never overlap.

---

# Principle 06

Translation Authority

The Mapper Runtime is
the Translation Authority.

Its responsibility is

translation,

not interpretation.

Translation preserves Reality.

Translation never generates meaning.

---

# Principle 07

Framework Boundary

The Reality Acquisition Framework
ends at the Integration Runtime.

```
Reality
        │
        ▼
Reality Acquisition Framework
        │
        ▼
Import Contract
═══════════════════════════════
Framework Boundary
═══════════════════════════════
        │
        ▼
Product Runtime
```

Everything beyond the
Import Contract belongs to

the Product Runtime.

---

# Principle 08

Meaning Boundary

Meaning is forbidden inside
the Reality Acquisition Framework.

The framework must never

- classify products

- infer specifications

- generate semantic labels

- detect AI PCs

- rank products

These responsibilities belong
to later Runtime specifications.

---

# Principle 09

Implementation Independence

Implementations may differ.

Examples

- Playwright

- Requests

- FTP

- REST API

- GraphQL

- Browser Automation

Implementation choices
must never affect

Runtime Responsibilities

or

Runtime Contracts.

Evolution
