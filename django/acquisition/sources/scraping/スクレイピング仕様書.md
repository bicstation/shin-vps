# SHIN CORE LINX Specifications

This repository defines the architecture and contracts of
the SHIN CORE LINX platform.

Every specification has a clearly defined responsibility.

Implementations may differ.

Responsibilities must remain consistent.

---

```
SHIN CORE LINX

│
├── 02. Runtime Contract Specification
│
├── 03. Product Runtime Specification
│

│
└── 05. Semantic Runtime Specification
```

---

# Scraping Framework Specification

---

# 1. Purpose

The purpose of the Scraping Framework is
to preserve Reality.

Scraping never generates semantic meaning.

Reality is acquired first.

Meaning is generated later by
independent runtimes.

---

# 2. Core Philosophy

Reality differs by source.

Reality is preserved consistently.

Meaning is generated later.

Every Runtime has a single responsibility.

Implementations may differ.

Responsibilities must remain consistent.

---

# 3. Runtime Principle

Every Runtime

- has one responsibility
- produces one Runtime Contract
- never depends on the internal implementation
  of another Runtime

Adjacent runtimes communicate only through
Runtime Contracts.

---

# 4. Source Architecture

Each scraping source owns its own implementation.

Examples

- Directory structure
- Fetch strategy
- HTML parser
- Runtime pipeline
- Observation strategy

These may differ completely.

Only Runtime Responsibilities are standardized.

---

# 5. Runtime Overview

Typical pipeline

Reality
    ↓
Acquire Runtime
    ↓
Observation Runtime
    ↓
Formatter Runtime
    ↓
Mapper Runtime
    ↓
Integration Runtime

A source may omit runtimes
or introduce additional runtimes.

The Framework standardizes responsibilities,
not implementation order.

---

# 6. Design Principles

Reality First

Observation First

Runtime Contract First

Single Responsibility

Translation Authority

The Runtime Contract is the only supported
interface between runtimes.

---

# 7. Scope

This specification defines only
the Scraping Framework.

It does not define

- Product Runtime
- AI Runtime
- Semantic Runtime

Those responsibilities are defined by
independent specifications.

# Runtime Contract Specification

---

# 1. Purpose

The purpose of this specification is to define
the Runtime Contracts shared between adjacent runtimes.

A Runtime Contract is the only supported interface
between runtimes.

Runtime implementations may change.

Runtime Contracts must remain compatible.

---

# 2. Runtime Contract

Every Runtime produces exactly one Runtime Contract.

```
Runtime
        │
        ▼
Runtime Contract
        │
        ▼
Next Runtime
```

The next Runtime must depend only on
the Runtime Contract.

It must never depend on the implementation
of the previous Runtime.

---

# 3. Runtime Responsibilities

Every Runtime owns

- Input Contract
- Output Contract

The Runtime Contract belongs to the Runtime.

It is not shared with any other Runtime.

---

# 4. Contract Stability

Implementations may change.

HTML parsers may change.

Builders may change.

Repositories may change.

Runtime Contracts should remain stable whenever possible.

When a Runtime Contract changes,

all adjacent runtimes must be updated together.

---

# 5. Contract Hierarchy

Each Runtime owns one contract.

```
Acquire Runtime

↓

Acquire Contract

↓

Observation Runtime

↓

Observation Contract

↓

Formatter Runtime

↓

Formatter Contract

↓

Mapper Runtime

↓

Mapper Contract

↓

Integration Runtime

↓

Integration Contract
```

Each contract is independent.

A Runtime must never bypass
another Runtime Contract.

---

# 6. Runtime Independence

Each Runtime can be developed independently.

Each Runtime can be tested independently.

Each Runtime can be replaced independently.

As long as its Runtime Contract
remains compatible.

---

# 7. Design Principle

Runtime Contracts define communication.

Runtime implementations define behavior.

These responsibilities must remain separate.

# Runtime Contract Specifications

Each Runtime owns an independent Runtime Contract.

A Runtime Contract defines only

- Input
- Output
- Responsibilities

It never defines implementation.

---

# Contract List

## 01. Acquire Runtime Contract

```
Reality
        │
        ▼
Acquire Runtime
        │
        ▼
Acquire Contract
```

Defines

- HTML
- Source URL
- Metadata

---

## 02. Observation Runtime Contract

```
Acquire Contract
        │
        ▼
Observation Runtime
        │
        ▼
Observation Contract
```

Defines

Observable Reality

Examples

- raw_title
- raw_price
- raw_image
- raw_html

No normalization.

No semantic meaning.

---

## 03. Formatter Runtime Contract

```
Observation Contract
        │
        ▼
Formatter Runtime
        │
        ▼
Formatter Contract
```

Defines

Normalized Reality.

Examples

- normalized text
- normalized arrays
- runtime safety

Formatter never changes meaning.

---

## 04. Mapper Runtime Contract

```
Formatter Contract
        │
        ▼
Mapper Runtime
        │
        ▼
Mapper Contract
```

Defines

Canonical Runtime used by the
Integration Runtime.

Typical responsibilities

- URL normalization
- Price normalization
- Affiliate URL generation

Mapper never performs semantic classification.

---

## 05. Integration Runtime Contract

```
Mapper Contract
        │
        ▼
Integration Runtime
        │
        ▼
Import Framework
```

Defines

The interface between

Scraping Runtime

and

Product Runtime.

Integration Runtime is the final Runtime
defined by the Scraping Framework.

---

# Runtime Independence

Each Runtime Contract

- may evolve independently

- may add fields

- may remove internal implementation

as long as

its adjacent Runtime Contract remains compatible.

# Product Runtime Specification

---

# 1. Purpose

The Product Runtime transforms
Import Contracts into persistent PCProduct objects.

The Product Runtime begins after
the Scraping Framework.

It is an independent Runtime.

---

# 2. Scope

This specification defines

- Import Runtime
- Import Normalizer
- Product Builder
- Semantic Builder
- Model Mapper
- Repository

It does NOT define

- HTML Parsing
- Observation
- Formatter
- Scraping Pipeline

Those responsibilities belong to the
Scraping Framework.

---

# 3. Runtime Pipeline

Import Contract
        │
        ▼
Import Normalizer
        │
        ▼
Builder
        │
        ▼
Semantic Builder
        │
        ▼
Model Mapper
        │
        ▼
Repository
        │
        ▼
PCProduct

---

# 4. Runtime Responsibilities

## Import Runtime

Responsibilities

- Load Import Contract
- Validate Contract
- Execute Runtime

Never

- Parse HTML
- Observe Reality

---

## Import Normalizer

Responsibilities

- Normalize Import Contract
- Runtime Safety
- Default Values

Never

- Generate Semantic Meaning

---

## Product Builder

Responsibilities

- Build Product Runtime
- Prepare Repository Payload

Never

- Persist Database

---

## Semantic Builder

Responsibilities

- Build Backend Runtime
- Generate Runtime Defaults

Never

- Parse HTML

---

## Model Mapper

Responsibilities

- Convert Runtime
- Build ORM Payload

Never

- Generate Observation

---

## Repository

Responsibilities

- Save PCProduct
- Update PCProduct

Never

- Build Runtime

---

# 5. Runtime Principle

Every Runtime owns

one responsibility

one input

one output

one Runtime Contract

Implementations may change.

Runtime Contracts should remain stable.

---

# 6. Output

The Product Runtime produces

PCProduct

which becomes the canonical product model
used by all Backend services.

# Runtime Interface Specification

---

# Purpose

This specification defines the public interface
of every Runtime.

It does not define implementation.

It defines only

- Input
- Output
- Entry Point

---

# Runtime Interface

Every Runtime exposes exactly one Entry Point.

```
Input Contract
        │
        ▼
Runtime
        │
        ▼
Output Contract
```

The Entry Point is the only supported interface.

---

# Runtime Structure

Every Runtime should follow
the same structure.

```
Constants

↓

Helpers

↓

Runtime Logic

↓

Persistence

↓

Entry Point
```

Implementation details may differ.

---

# Runtime Entry Point

Every Runtime provides

```
main()
```

or

```
run()
```

as its public interface.

Internal helper functions
must remain private.

---

# Runtime Communication

A Runtime communicates only through

Input Contract

↓

Output Contract

A Runtime must never

- inspect another Runtime's implementation
- modify another Runtime's internal state

---

# Runtime Independence

Each Runtime

- can be replaced

- can be tested

- can be executed

independently.

Only the Runtime Contract
must remain compatible.

---

# Design Principle

A Runtime is a black box.

Only its interface is public.

Everything else is implementation.
